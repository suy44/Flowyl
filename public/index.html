Features

One endpoint. Two superpowers.

🔒

Idempotency Shield

Every request gets a unique key. If the same key is seen within the TTL window, Flowyl returns the cached response instantly — the real API is never called twice.

  • Custom TTL per request (1 min → 30 days)
  • Cached response returned on dedup
  • Manual key invalidation via API
  • Namespaced per API key — zero cross-talk
⚡

Smart Rate Limiter

Requests that would trigger a 429 are automatically queued and drained at the target API's actual rate. Respects Retry-After headers natively.

  • Token bucket algorithm per destination
  • Pre-configured presets for popular APIs
  • Automatic retry with exponential backoff
  • Poll-based status tracking
🛡️

SSRF Protection

Private/internal IPs are blocked automatically.

🌐

CORS Ready

Full CORS support — call from anywhere.

🌍

Edge Deployed

Runs globally on the edge — sub-50ms dedup checks worldwide.

🎯

Zero Config

No Redis, no Postgres, no infra. Just an HTTP header.

How It Works

Three headers. That's it.

Wrap your outbound API call in a POST to Flowyl. Add the headers. Done.

01

Add Your Key

Set X-Flowyl-Key to a unique identifier for this action. Example: send_invoice:order_4821

X-Flowyl-Key: send_invoice:order_4821
02

Pick a Preset

Optionally set X-Flowyl-Preset to enable smart rate limiting for the target API.

X-Flowyl-Preset: airtable
03

Flowyl Handles the Rest

Duplicate? Returns cached response. Rate limited? Queued and retried. Success? Stored and returned.

✅ executed 🔄 deduplicated ⏳ queued
